Castor Docker

Décrire sa stack Docker avec Castor

Un plugin Castor

  • stack décrite en PHP
  • compose généré
  • tâches prêtes à l'emploi
$ castor composer require castor-php/docker

Un exemple

#[AsListener(RegisterServiceEvent::class)]
function register_services(RegisterServiceEvent $event): void
{
    $postgres = new PostgresService();
    $event->addService($postgres);

    $event->addService(
        (new PHPService('app'))
            ->withDirectory(__DIR__)
            ->withDomain('app.demo.test')
            ->link($postgres)
    );
}

Ce que tu obtiens

  • PHP + Postgres
  • application déjà configurée
  • https://app.demo.test
  • tâches prêtes

  • à toi

  • généré depuis castor.php
  • à chaque run
  • ne pas éditer

  • surcharges locales
  • jamais touché
  • à toi
# compose.yaml
include:
   - path:
         - compose.generated.yaml
         - compose.override.yaml

Où personnaliser ?

Le contexte et les services maison alimentent les services ; ensuite la chaîne d'events, en dernier recours. Prendre le niveau le plus haut possible.

1Le contexte

#[AsContext(default: true)]
function default_context(): Context
{
    return new Context([
        'root_domain'    => 'demo.test',
        'registry'       => 'ghcr.io/org/demo',
        'build_parallel' => true,
        'docker_profiles' => ['default'],
    ]);
}
Global au projet : domaine racine, registry, nom du projet, router, worktrees…

2Les services

#[AsListener(RegisterServiceEvent::class)]
function register_services(RegisterServiceEvent $event): void
{
    $event->addService(new RedisService());

    $event->addService(
        (new PHPService('app'))
            ->withDomain('app.demo.test')
            ->addExtension('redis')
            ->withPhpIni(['memory_limit' => '1G'])
    );
}
90 % des besoins · API fluide with*() · ordre des appels libre

3Le Dockerfile Twig

# syntax=ghcr.io/castor-php/twig-dockerfile:0.1
{% extends 'Dockerfile.frankenphp' %}

{% block php_base %}
    {{ parent() }}
RUN apt-get update && apt-get install -y figlet
{% endblock %}
->withDockerfile(__DIR__ . '/Dockerfile')
L'image : paquet système, outil, conf nginx / Caddy · blocs php_base · frontend · worker · builder · on surcharge, on ne copie pas

4Le ComposeBuilder

#[AsDockerComposeBuilder]
function add_adminer(ComposeBuilder $builder, Context $ctx): void
{
    $builder
        ->service('adminer')
            ->image('adminer:5')
            ->withHttpRouting('adminer.' . $ctx['root_domain'], 8080)
            ->profile('default')
        ->end();
}
Service spécifique au projet · non réutilisable · modifier un service existant · DockerComposeBuilderEvent pour l'ordre

5DockerComposeWriteEvent

#[AsListener(DockerComposeWriteEvent::class)]
function limit_postgres_memory(
    DockerComposeWriteEvent $event,
): void
{
    $event->compose['services']['postgres']
        ['deploy']['resources']['limits']['memory'] = '256m';
}
Trappe de secours · tableau brut · deploy, logging, secrets, x-*
Rien de validé · l'erreur sort côté docker compose
